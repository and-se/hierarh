# Как подготовить данные для работы

В каталоге `data` содержатся всех входные и выходные файлы программы. В каталоге `data/patch` - поправки, которые мы вносим при обработке входных данных.

## Настраиваем виртуальное окружение
В папке проекта (`hierarh`) выполняем команды:
```
# создаём независимую установку python в папке hierarh/env (=окружение env)
python3 -m venv env

# переключаемся в текущей консоли на работу с окружением env
# в дальнейшем эту команду надо выполнять всегда перед началом работы с проектом в новой консоли
source env/bin/activate

# ставим необходимые библиотеки
pip install -r requirements.txt
```

## БД для просмотра на основе json файла с раскрытыми сокращениями
Посетители сайта просматривают БД `hierarh.sqlite3`. Они могут отправлять комментарии - они сохраняются в БД `hierarh.comments.sqlite3`.

Для построения БД `hierarh.sqlite3` нужно положить в папку `data` файл `cafedra_articles_expand_abbrs.json`.
Это построенный на основ xml вёрстки книги json файл, в котором средствами ChatGPT раскрыты сокращения и аббревиатуры.

Далее строим БД командой
```python db.py build main```.
_NB! Мы делаем это в окружении env, а в нём команда python аналогична python3_

Если БД для комментариев ещё не построена, строим обе БД командой
```python db.py build all```

Другие варианты можно почитать, запустив команду
```python db.py```

После сборки надо посмотреть в файл `data/cafedra-episkop-fail.txt` - он должен быть пуст.
Если это не так, то какие-то строки о епископах не удалось распарсить и они сохраняются как подзаголовок в таблице епископов, а это криво.
Надо править входной файл либо парсеры.

**NB!** Под Windows надо запускать `python -Xutf8 db.py`, чтобы не было проблем с кодировкой при чтении файлов патчей.

## Настройка settings.py

Создаём копию файла settings-template.py с именем settings.py

В этом файле надо задать ключ шифрования FLASK_APP_SECRET_KEY - произвольная _секретная_ строка.

В словаре Users задаём логины и пароли пользователей, которые смогут логиниться и редактировать данные.

Данные для редактирования хранятся в отдельной БД `hierarh-edit.sqlite3`. При желании её имя можно изменить в settings.py, поменяв переменную EditDbName.

## Построение БД редактирования

Начальная БД редактирования строится отдельно на основе файлов из data/edit-init, в которой лежат файлы:
* `cafedra-edit.json` - разобранные исходные данные книги (с сокращениями) - это будет первая версия статьи о кафедре в истории правок.
* `cafedra-exp-abbrs-edit.json` - данные книги с раскрытыми при помощи ChatGPT сокращениями - это будет актуальная версия статьи о кафедре.
* `episkop-edit.json` - данные епископов из книги

что в нём вручную поправлены обнаруженные многочисленные ошибки в сносках. 
БД просмотра надо строить на его основе, но это требует что-то править в коде db.py - сейчас падает.

Для начала преобразуем описанные выше json-данные в html-документы, которые и будет в дальнейшем редактироваться:
```python edit/init_db_creator.py json```

Если в процессе преобразования будут обнаружены проблемы в каком-либо входном файле, 
то будет сформирован отчёт об ошибках "$имя_входного_файла_с_проблемой.errors.html".
Этот файл надо отправить авторам, чтобы они открыли его в браузере и увидели, в чём проблемы.
Самостоятельно посмотреть его также надо - возможно ошибки очевидные и можно поправить их самостоятельно.
Соответствующие входные файлы следует поправить --- для успешной конвертации никаких ошибок ни в одном из файлов быть не должно.

В результате в папке data/edit-init появятся одноимённые html файлы, на основе которых будет строиться БД редактирования.
Для создания БД редактирования запускаем команду:
```python edit/init_db_creator.py db```
